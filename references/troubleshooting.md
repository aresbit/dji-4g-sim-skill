## #1 切上网模式前必须先想资费

模块一旦以 CDC-ECM 上线，Mac 就有了一个**真实计费**的出口。
在动手切模式前确认三件事：

1. 套餐余量、是否漫游、漫游单价；
2. **IoT / 漫游卡的 APN 常与消费级不同，不要猜**——用运营商给的；
3. 是否有需要"只走 Wi-Fi"的场景（切过去再切回来要重启模块，几十秒）。

`[实测]` 参考机上模块一度成为系统默认路由，也就是说**在用户没意识到的情况下，
普通流量已经在走这张卡**。切模式前后都跑一次 `scripts/status.sh` 的第 4 节确认出口。

## #2 切到上网模式后短信/eSIM/AT 全废

**现象**：日志刷这些错误，界面里 eSIM 读到"未发现任何 eUICC"。

`[实测]`

```
call poll failed: USB AT command timed out without response
SMS poll failed: USB bulk write: LIBUSB_ERROR_PIPE
claim USB AT interface 5: LIBUSB_ERROR_ACCESS
USB AT bridge detached; waiting for a new enumeration: ... disconnected
```

**原因**：不是坏了。切成 CDC-ECM 后 macOS 的 `AppleUserECM` 驱动绑定了该
USB 接口，ModemCat 的 libusb 抢不到独占访问，AT 桥反复重连失败。

**处理**：接受它就是代价。要管卡就切回短信模式（`AT+QCFG="usbnet",0` + 重启模块）。
两种模式在 macOS 单机上不可兼得——这是平台限制，不是 ModemCat 的 bug。

## #3 能上网，但浏览器流量不走模块

**现象**：`status.sh` 里绑网卡实测是通的，但浏览器的公网 IP 不是蜂窝那个。

`[实测]` 默认路由被代理的 TUN 抢走了：

```
route -n get 1.1.1.1
    gateway: 198.18.0.1
  interface: utun1500        # 198.18.0.0/15 是 Clash/mihomo/Surge 等的合成网段
```

`netstat` 里明明有 `default → 192.168.225.1 en8`，但 `utun1500` 用
`0/1`、`128/1` 两条分割路由把它盖住了。所以**普通流量走代理，不走模块**。

**处理**（三选一）：

- 在代理软件里把 `EG25G-QDC507` 指定为直连 / 指定出口；
- 临时关掉 TUN 模式，让 `en*` 的默认路由生效；
- 按用途绑定源地址：`curl --interface en8 …`（诊断时最常用）。

## #4 拿到 192.168.225.x 但上不了网

`192.168.225.x` **只证明模块自己的 DHCP 在工作**，不证明它附着上了运营商。

判定要看三层，缺一不可：

1. `AT+CPIN?` → `READY`
2. 注册状态 `1`(本网) 或 `5`(漫游)：`AT+CREG?` / `AT+CGREG?`
3. **实际出网**：`scripts/status.sh` 的出口实测

顺带一个很强的旁证：如果网卡上有**运营商网段的 IPv6 全局地址**
（中国移动是 `2409:` / `240e:`），说明已经附着蜂窝网并有 IPv6 承载。
`[实测]` 参考机上就是这么确认的。

失败时按序排查：APN 是否匹配运营商 → SIM 套餐/是否停机 → 制式（是否锁网/仅 5G）→ 天线/信号 `AT+CSQ`。

## #5 USB 上完全看不到模块

**最常见的原因是 USB-C 线只供电、不传数据。** 先换一根确认能传数据的线，
再换端口 / 用带供电的 Hub（模块峰值供电不低）。

确认手段：

```sh
ioreg -p IOUSB -w0 -l | grep -A2 'idVendor" = 11427'
networksetup -listallhardwareports | grep -A1 EG25G
```

USB 层能看到但网络服务里没有 → 说明是短信模式（QMI），这是**正常的**，
不是故障。

## #6 卡里读不到 eUICC

**现象**：`eSIM overview failed: 未发现任何 eUICC … 解析 CCHO 响应失败: ERROR`

`[实测]`

两种可能，先分清：

1. **你插的是实体 SIM，不是 eUICC。** 那"读不到 eUICC"完全正常，
   实体卡没有 Profile 概念。
2. **是 eUICC，但当前在上网模式**——AT 通道被 ECM 驱动挤掉了（见 #2）。

判断方法：切回短信模式再读一次。仍读不到，才是真没有 eUICC。

## #7 切模式后设备消失一会儿

切换会触发 USB 重新枚举，设备**短暂消失 5–15 秒是正常的**，不是故障。
等页面重新识别；长时间不回来再停止程序、重新插拔模块后启动。

## #8 换卡后还是旧信息

模块重读卡和注册网络需要时间。刷新没用就停程序 → 拔卡换卡 → 重插 → 再启动。
切换 eSIM Profile 后也可能需要重启模块才更新状态。

## #9 Gatekeeper 拦截 / 提示"文件已损坏"

发行包是**临时签名、未经 Apple 公证**的。首次运行可能被拦。

- 首选：系统设置 → 隐私与安全性 → 选"仍要打开"。
- 仍报"已损坏"：回安装目录清隔离属性

  ```sh
  xattr -dr com.apple.quarantine <安装目录>
  ```

  > 只对**从可信 Release 下载、且 SHA-256 核对通过**的文件这么做。
  > 本 skill 的 `bootstrap.sh` 已经在校验通过后才清隔离属性。

## 隐私与合规

- 使用蜂窝数据前确认套餐、漫游资费与流量上限。
- 境外 SIM/eSIM 在资费不明时**不要**切上网模式。
- 不要公开 EID、ICCID、IMSI、完整手机号、验证码。
- 发布日志/截图前先抹掉上述字段。
- 遵守所在地法律、运营商协议与 eSIM 服务条款。
